SnowlineRally · 全屏白屏闪烁修复记录

HarmonyOS（2 in 1）Web 组件最大化后持续白闪问题的排查、定位与修复全过程

已修复 · 用户实测验证 2026-11-16 根因：ASYNC_RENDER 独立送显（DSS 硬件合成）缺陷 修复：renderMode: RenderMode.SYNC_RENDER

1问题概述

现象：应用在 2 in 1 设备上以默认窗口尺寸（浮动窗口）运行游戏完全正常；一旦点击「最大化」进入全屏（窗口铺满屏幕），画面立即开始持续白屏闪烁；还原窗口后恢复正常。

用户观察到的关键特征（后经确认）：
  • 全屏期间持续闪（游玩中、暂停时都闪），不是只在最大化切换瞬间闪；
  • 白屏覆盖整个窗口；
  • 前端图标 UI 不闪，只有后面的图像在闪 —— 说明 UI 层与背景图像层走的是不同的显示路径。

2排查过程

  • 排除：渲染进程崩溃 / 无限刷新循环
    此前曾存在另一个独立问题：系统回收渲染进程（SIGKILL，RenderExitReason.ProcessWasKilled=1）后旧恢复逻辑会在 onPageEnd 无条件重置计数，导致「回收 → 刷新 → 重载」死循环式白闪。该问题已通过时间感知的崩溃预算（60 秒稳定运行才重置）+ 后台延迟单次重载修复。但本次全屏白闪期间日志显示 GPU 全程 60fps 正常渲染、无 KillRenderProcess、无重载 —— 属于另一个问题。
  • 排除：WebGL 上下文丢失 / 表面重建
    全屏 2.8 秒窗口内日志无任何 context lost / restore；NotifyFirstRealSwapBuffer 频率与稳定期一致（约 60 次/秒），needs_notify_first_swap_buffer: 1 从未出现 —— 无表面反复重建。
  • 排除：窗口管理器 / 系统窗口层干扰
    全屏期间无 WMS 窗口层级事件风暴、无系统 overlay 显示/隐藏记录；NWeb 尺寸仅一次性变化（默认窗口 → 最大化），无尺寸振荡。
  • 排除：游戏内全屏 / 分辨率设置
    全文检索确认游戏 HTML 内无任何「全屏 / 分辨率 / 画质」设置项，也不调用 requestFullscreen —— 用户所述「全屏」即窗口最大化。
  • 关键实验：闪烁发生时连续截屏采样
    用户看着全屏画面正在闪烁的同时，以约 1.1 秒/张的节奏连续抓取 40 张全屏截屏（覆盖约 45 秒），用纯 Node PNG 解码器逐像素统计白度。结果：40 张全部是稳定的游戏画面，零白帧，仅存在细微动画漂移。窗口状态同时确认游戏正处于最大化可见状态（Mode=1，Z 序最高应用窗口）。
    ⇒ 结论：白闪不出现在合成器输出里 —— 问题位于合成器与显示面板之间的输出路径。
  • 文档定位：Web 组件渲染模式与 DSS
    查阅《Web组件渲染模式》文档：Web 默认 ASYNC_RENDER 模式下，Web 组件作为图形 surface 节点独立送显，由 DSS（显示子系统）硬件合成直扫输出；SYNC_RENDER 模式下 Web 作为 canvas 节点跟随系统组件一起送显，不走 DSS 合成。

3根因

Web 默认 ASYNC_RENDER 渲染模式下，Web 内容作为独立图形 surface 交给 DSS（显示子系统）硬件合成直扫。本机（2 in 1）在窗口最大化时，DSS 对这块接近全屏宽度的 Web surface 的扫描输出存在缺陷：
  • 缓冲区内容本身完好（合成器截屏全部正常、GPU 60fps 正常渲染）；
  • 但面板扫描输出交替读出空/未初始化缓冲 → 整窗白帧，形成持续白闪；
  • 「UI 不闪、背景闪」与 DSS 分层直扫行为吻合 —— 不同内容层被分配到不同的显示合成路径，仅走直扫的背景层受影响；
  • 默认窗口尺寸未触发该大 plane 路径，因此窗口模式正常。

注：截屏由合成器读取正常缓冲生成，因此永远「拍不到」白帧；这是本问题初期难以用日志与截屏定位的原因。

4修复方案

将 Web 组件改为同步渲染模式：Web 作为 canvas 节点跟随系统组件一起经 RenderService GPU 合成后统一送显，绕开 DSS 对 Web surface 的独立直扫路径。

改动位置

app/entry/src/main/ets/pages/Index.ets（Web 组件构造参数）：

// 修复前：默认 ASYNC_RENDER，Web 独立送显（DSS 硬件合成），最大化时白闪
- Web({ src: $rawfile('snowline-rally.html'), controller: this.controller })

// 修复后：SYNC_RENDER，Web 作为 canvas 节点跟随系统组件一起送显
+ Web({ src: $rawfile('snowline-rally.html'), controller: this.controller, renderMode: RenderMode.SYNC_RENDER })

两种渲染模式对比

ASYNC_RENDER（默认）SYNC_RENDER（本次采用）
Web 形态图形 surface 节点，独立送显图形 canvas 节点，跟随系统组件一起送显

8经验总结

  • 「日志正常 + 用户看到异常」时，怀疑合成器以下的显示输出路径：GPU 帧率、缓冲内容、WMS 事件全正常而用户看到闪，说明缺陷在 DSS / 扫描输出层，日志与截屏均不可见。
  • 截屏对照实验是判定利器：让用户盯着闪烁现场，同时连续截屏做像素统计。截屏零白帧 ⇒ 闪烁在合成器之下；截屏白帧 ⇒ 内容层问题。
  • ArkWeb 渲染模式选择：ASYNC_RENDER（独立 surface + DSS 硬件合成）在部分设备的最大化场景存在直扫缺陷；出现「仅全屏闪、截屏拍不到」时优先尝试 RenderMode.SYNC_RENDER。
  • 「UI 不闪、背景闪」是分层显示的指纹：不同内容层被分配到不同显示路径（DSS 直扫 vs GPU 合成），只有走问题路径的层受影响。
  • 调试工具备忘：hidumper -s WindowManagerService -a '-a' 查窗口 Mode/Z 序/矩形；snapshot_display -f x.png -t png 截屏（注意 .png 后缀必须搭配 -t png，否则报「suffix must be .jpeg」）；纯 Node PNG 解码 + 白度统计可在无图像库环境下完成像素级分析。
